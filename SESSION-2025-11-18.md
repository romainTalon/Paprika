## 🐛 Bugs Corrigés

### 1. Erreur snake_case/camelCase dans CookbookService
**Problème** : "Une erreur s'est produite lors de l'enregistrement" lors de la création de cookbook.

**Cause** : Le service utilisait des noms de colonnes camelCase mais Supabase attend snake_case.

**Solution** :
- Ajout fonction `mapDbRowToCookbook()` pour transformer les données
- Correction de toutes les méthodes CRUD
- Application du même pattern à RecipeService

**Fichiers impactés** :
- `src/services/cookbook.service.ts`
- `src/services/recipe.service.ts`

---

### 2. Erreur "Hooks Order" dans RecipeListScreen
**Problème** : `Error: Rendered more hooks than during the previous render`

**Cause** : Les hooks `useCallback` étaient déclarés **après** des `return` conditionnels, violant les Rules of Hooks.

**Solution** :
- Déplacer tous les hooks au début du composant
- Placer les conditions de return APRÈS tous les hooks
- Pattern appliqué :
  1. Hooks (useState, useQuery, useCallback, etc.)
  2. Logique
  3. Conditions de return
  4. Render principal

**Fichier impacté** :
- `app/cookbooks/[id].tsx`

---

### 3. Erreur TypeScript dans validation Zod
**Problème** : Erreurs de compilation avec Zod v4 (`invalid_type_error` n'existe pas).

**Cause** : Syntaxe Zod changée entre versions.

**Solution** :
- Remplacer `{ invalid_type_error: "..." }` par `{ message: "..." }`
- Remplacer `error.errors` par `error.issues`
- Simplifier `z.enum()` errorMap

**Fichiers impactés** :
- `src/lib/validations/recipe.validation.ts`
- `app/recipes/create.tsx`

## 🔧 Décisions Techniques

### 1. Mapping snake_case/camelCase
**Décision** : Fonction de mapping dans chaque service

**Raison** :
- Type safety garantie
- Consistance dans toute l'app
- Autocomplétion fonctionne
- Pattern réutilisable

**Implémentation** :
```typescript
function mapDbRowToRecipe(row: any): Recipe {
  return {
    id: row.id,
    userId: row.user_id,
    cookbookId: row.cookbook_id,
    coverImageUrl: row.cover_image_url,
    isDefault: row.is_default,
    // ... etc
  };
}
```

### 2. Validation Zod
**Décision** : Schémas Zod composables

**Raison** :
- Type inference automatique
- Schémas réutilisables
- Messages d'erreur localisés
- Léger (8KB)

**Schémas** :
- `recipeIngredientSchema`
- `recipeStepSchema`
- `createRecipeSchema`

### 3. Pattern Hooks React
**Décision** : Tous les hooks avant les returns conditionnels

**Raison** :
- Respecte Rules of Hooks
- Évite bugs de re-render
- Best practice React

**Structure** :
1. Hooks
2. Logique
3. Returns conditionnels
4. Render principal

## 🎓 Leçons Apprises

1. **Always mapper DB data** : Toujours transformer snake_case → camelCase immédiatement après fetch
2. **Hooks order matters** : Jamais de hooks après un return conditionnel
3. **Zod version compatibility** : Vérifier la syntaxe selon la version installée
4. **Plan before code** : Les 45 minutes de planification initiale ont économisé des heures de refactoring
5. **Type safety first** : Les erreurs TypeScript sont vos amies, pas vos ennemies
